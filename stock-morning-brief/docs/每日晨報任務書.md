# 每日晨報任務書（流程、模板與正確性防護）

> ⚠️ 本簡報是資訊彙整，不是投資建議；永遠不做任何下單／交易動作。

## 誰在執行

**每天自動跑的是 `brief.py`，不是 AI 對話。**

| 步驟 | 誰做 | 怎麼做 |
|---|---|---|
| 產圖＋健檢箭頭 | 程式 | `brief.py` 呼叫 `charts.py` |
| **市場重點** | **AI** | `brief.py` 用 `claude -p` 背景呼叫，只給網搜權限、不留 session |
| 查核市場重點 | **AI** | 另開一次乾淨呼叫，逐條比對來源（見下方第 3 層防護） |
| 組簡報、歸檔、上雲端、推播 | 程式 | `brief.py` 確定性執行，順序寫死 |

排程直接叫 `brief.py`（Windows 用 `install_schedule.ps1`，macOS/Linux 用 cron）。
**不要**把整份流程交給 AI 對話式排程——那會每天開一個新對話、遇到未授權指令
還會卡在權限詢問等人按允許。

AI 那段掛掉（未登入／網路異常）**不會拖垮整份晨報**：市場重點改成警告字樣，
健檢與圖表照常推出。

## 流程

### 1. 產圖＋健檢
`charts.py` 產出到 `config.yaml` 的 `archive_dir`：`YYYY-MM-DD_圖/` 與 `YYYY-MM-DD_健檢.md`。
箭頭由程式的技術訊號投票算出，**AI 不參與、也不准自己判**。

若行情源抓不到資料（限流時會發生）導致健檢整表空掉，`brief.py` 會自動退回
最近 7 天內有資料的健檢並註明日期——空白的健檢區對使用者毫無價值。

### 2. 市場重點（唯一需要判斷力的一段）
**規則**：只取 24 小時內新聞（週末可放寬到 72 小時）；每則必附來源連結；
查不到就少寫幾條；禁止憑空編造數字。

範圍（濃縮成 5~8 條 bullet）：
- 大盤動態一句話（依 config 的 `market` 決定台股／美股／兩者）
- 現在市場的熱門趨勢／題材（資金流向、討論熱點）
- 影響今天開盤的 1~2 個關鍵變數

### 3. 組簡報（固定模板）

```markdown
# 📈 股票晨報 YYYY-MM-DD（週X）

## 🔥 市場重點
- {重點，一句話}｜[來源](url)
- …（5~8 條）

🩺 自選股健檢
{直接貼入 charts.py 產的 YYYY-MM-DD_健檢.md 全文}

（K線圖隨後送達 📊）

---
📌 本簡報為 AI 自動彙整之公開資訊，僅供參考，**非投資建議**。
```

休市日改成「本週回顧＋下週展望」，標題加「（假日版）」。

### 4. 歸檔與推播（順序固定：文字先、圖後）
1. 簡報存 `<archive_dir>/YYYY-MM-DD_晨報.md`
2. `storage: gdrive` 時：`gws drive +upload "<檔案>" --parent <gdrive_folder_id>`
3. `python notify.py "<簡報檔>"`
4. `python notify.py --photos "<archive_dir>/YYYY-MM-DD_圖"`
5. 失敗自動重試並寫入 `run_history.log`；圖片單張失敗不中斷，重跑會自動跳過已送出的

## 正確性三層防護

這是本專案最重要的設計。起因是一個真實事故：AI 把某則利率新聞的方向詞寫錯，
而使用者是**拿這份做投資判斷**的——**方向寫反比沒寫更糟**。

| 層 | 擋什麼 | 做法 |
|---|---|---|
| 1 事實基準 | 數字錯 | `quotes.py` 先抓好指數與自選股的收盤／日／週漲跌，塞進 prompt 並明令「照抄不准自填」。能用程式算的就不讓 AI 猜。 |
| 2 方向詞清單 | 方向寫反 | prompt 內 `DIRECTION_GUARD` 明列高風險對照組（升息↔降息、鷹派↔鴿派、beat↔miss…），要求寫這類詞前回頭核對來源原文，沒把握就整條不寫。 |
| 3 查核 pass | 漏網的錯＋幻覺＋來源違規 | **另開一次乾淨的 AI 呼叫**當「查核員」，逐條打開來源比對；有錯就改、無法證實的標 ⚠️、來源不在白名單的整條刪掉。 |

### 三個關鍵設計決定

**① 查核一定要是獨立呼叫。**
同一段 context 裡叫模型「自己再檢查一次」幾乎無效——它會維護自己剛寫的東西。
換一次乾淨的 context、給它「查核員」而非「作者」的身分，才抓得到。

**② 查核員必須有「改動門檻」。**
這是踩過坑才加的：查核 prompt 原本只寫「有錯的條目改成正確版本」，
結果它把一條**原本正確**的敘述改反了——因為它憑印象覺得可疑就動手。
現在明訂：只有**實際打開來源、讀到相反內容**才可以改；「我覺得應該是相反的」
不構成理由，一律保持原樣並標 ⚠️ 讓使用者自己判斷。

> 寫進 prompt 裡的原話：**改壞比漏抓更糟**——漏抓只是少擋一個錯，
> 改壞是親手製造一個錯，而且使用者會以為它已經被查核過。

**③ 查核不能反過來擋掉整份晨報。**
查核失敗、逾時、或回傳結果剩不到 3 條（代表它沒照規則做），
一律自動退回未查核的原稿照常推播。

### 這套防護的極限（誠實說明）

查核員也是 LLM，沒有即時市場知識，唯一依據是來源原文。它會降低錯誤率，
**但不可能歸零**。真正的最終保險是每條都掛著的**來源連結**與 ⚠️ 標記——
晨報的定位是「快速掃描 + 指路」，要據以行動的那條，點進去讀原文永遠是對的。
