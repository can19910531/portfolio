## 這個專案在乎的事：AI 說的話，憑什麼可以信？

多數「AI 幫你寫報告」的工具，你沒辦法判斷它是不是在唬爛。這個專案的立場是：

> **能用程式算的，就不要讓 AI 猜；AI 寫的東西，要能被查核。**

趨勢箭頭、收盤價、漲跌幅全部由程式計算。AI 只負責「網搜市場重點」這唯一需要判斷力的一段——而且產出後還要再過一道**獨立的查核**，逐條打開來源比對，證實不了的就標 ⚠️ 給你自己判斷。

<details>
<summary>🛡️ 展開看完整的「正確性三層防護」設計與踩過的坑</summary>

起因是一個真實事故：AI 把某則利率新聞的方向詞寫錯了。使用者是**拿這份做投資判斷**的——**方向寫反比沒寫更糟**。於是有了這三層：

| 層 | 擋什麼 | 做法 |
|---|---|---|
| **1 事實基準** | 數字錯 | `quotes.py` 先抓好指數與自選股的收盤／日／週漲跌，塞進 prompt 明令「照抄不准自填」 |
| **2 方向詞護欄** | 方向寫反 | 明列高風險對照組（升息↔降息、鷹派↔鴿派、beat↔miss…），要求寫這類詞前回頭核對原文，沒把握就整條不寫 |
| **3 查核 pass** | 漏網的錯、幻覺、來源違規 | **另開一次乾淨的 AI 呼叫**當查核員，逐條打開來源比對；有錯就改、無法證實的標 ⚠️、來源不在白名單的整條刪掉 |

**三個踩過坑才學到的設計決定：**

**① 查核必須是獨立呼叫。** 同一段 context 裡叫模型「自己再檢查一次」幾乎無效，它會維護自己剛寫的東西。換乾淨 context、給「查核員」而非「作者」的身分才有效。

**② 查核員必須有改動門檻。** 最初的查核 prompt 只寫「有錯就改成正確版本」，結果它把一條**原本正確**的敘述改反了——因為它憑印象覺得可疑就動手。現在明訂：只有實際讀到來源相反內容才准改，「憑印象覺得怪」一律保持原樣並標 ⚠️。寫在 prompt 裡的原話是：

> *改壞比漏抓更糟——漏抓只是少擋一個錯，改壞是親手製造一個錯，而且使用者會以為它已經被查核過。*

**③ 查核不能反過來擋掉整份晨報。** 查核失敗、逾時或結果異常，一律退回原稿照常推播。

**④ 來源白名單。** 未限制來源時，實測 12 份簡報引用了 38 個不同網域，其中混進個人寫作平台、內容農場、新聞聚合站，甚至通膨計算器這種工具站。現在可以在 `config.yaml` 指定只信任哪些媒體，安裝時 AI 會把預設清單攤開給你看再問要不要增補。

**誠實說明極限**：查核員也是 LLM，沒有即時市場知識，唯一依據是來源原文。這套防護降低錯誤率但**不可能歸零**。真正的最終保險是每條都掛著的來源連結與 ⚠️ 標記——晨報的定位是「快速掃描 + 指路」，要據以行動的那條，點進去讀原文永遠是對的。

</details>

**為什麼用系統排程器，而不是 AI 工具內建的排程功能？**

早期版本把整份流程交給 AI 對話式排程，實際跑下來三個問題：每天開一個**新對話**（對話列表很快被灌爆）、遇到未授權指令會**跳權限詢問**等人按「允許」（沒人按就整份卡死）、只在 AI 工具閒置時才觸發（錯過時間會延後好幾小時甚至重複執行）。

改成系統排程器直接跑 `brief.py` 之後：不開對話、不問權限、不跳通知，Windows 上用 `pythonw.exe` 連視窗都不會閃。AI 只在需要判斷力的那一段被呼叫，用完就結束（`--no-session-persistence`，不留任何 session 檔）。

<summary>❓ 常見問題</summary>

**電腦關機的話晨報會不會漏掉？**
會。排程需要電腦開著且在登入狀態。Windows 版有設定「錯過時間會在開機後自動補跑」，所以晚開機還是收得到，只是時間晚一點。

**我的持股資料會外流嗎？**
不會。自選股清單存在你電腦上的 `config.yaml`（已 gitignore），行情從 Yahoo Finance 公開資料抓，全程在你自己的電腦上跑。AI 呼叫只授予網搜權限（`--allowedTools WebSearch,WebFetch`），碰不到你的檔案。

**「市場重點」那段一定要嗎？**
不用。`config.yaml` 把 `ai.enabled` 設成 `false`，晨報就只有健檢箭頭＋K線圖，一樣每天準時送達，而且完全不需要 AI CLI。

**要花錢嗎？**
行情（Yahoo Finance）和推播（Telegram Bot）都免費。「市場重點」那段要呼叫 AI CLI，用的是你自己的 AI 訂閱或 API 額度，每天一次、量很小。

**怎麼改自選股 / 推播時間？**
直接編輯 `config.yaml`，或叫你的 AI「讀 docs/初始設定任務書.md 重跑一次訪談」。

**跑起來怪怪的，怎麼查？**
看專案資料夾裡的 `last_run.log`（上一次執行的完整輸出）和 `run_history.log`（歷史累積）。把 log 貼給你的 AI 通常就能診斷。

# 🤖 給 AI 的安裝指南

> **以下是寫給 AI 讀的執行指南，人類使用者可以略過。**
> 如果你是 AI，而使用者請你安裝這個專案 —— 從這裡開始，照著做完即可。

## ⚠️ 開始之前：先確認你拿到的是完整原文

如果你是**透過網頁抓取工具**讀到這份文件的，你很可能拿到的是**經過摘要的版本**——
實測過，摘要版會記錯章節標題、漏掉步驟細節。照著摘要版做會裝壞。

開始訪談前，先確保你有完整原文，依你的能力擇一：

1. **能執行指令** → `git clone https://github.com/can19910531/portfolio.git`，
   然後讀本機的 `portfolio/stock-morning-brief/README.md` 與 `docs/初始設定任務書.md`
2. **只能抓網頁** → 改讀 `raw.githubusercontent.com` 的原始檔（不是 github.com 網頁）：
   `https://raw.githubusercontent.com/can19910531/portfolio/main/stock-morning-brief/README.md`
3. **兩者都不行** → 請使用者把 README 原文整份貼給你，不要憑摘要開始

自我檢查：你應該要能看到「訪談（八題，一次一題）」這個小節，而且第 3 題是「新聞來源」
並帶有 ⚠️ 標記。看不到就代表你手上的不是完整版，**先取得原文再繼續**。

## 你的任務

逐題訪談使用者 → 產生 `config.yaml` 與 `.env` → 實測推播 → 建立每日排程。
完成後使用者每天早上會自動在 Telegram 收到晨報。

**原則**：一次只問一題、用使用者的語言、每題都給預設值、**不要求使用者懂程式**。
使用者是來用工具的，不是來學 Python 的。

## 第 0 步：先判斷你屬於哪一種

| 你的能力 | 怎麼做 |
|---|---|
| **能執行指令、讀寫檔案**（Claude Code、Cursor、有終端機權限的 agent） | 直接動手做完全部步驟，只在需要使用者決定或提供機密時才問 |
| **只能對話**（ChatGPT、Claude 網頁版） | 改成「你給指令、使用者貼到終端機執行、回報結果給你」的模式。**每次只給一段指令**，等使用者回報再給下一段，不要一次丟十行 |

不確定的話，先問使用者：「我可以直接操作你的電腦（執行指令、建立檔案）嗎？還是需要我給你指令、你自己貼到終端機執行？」

## 第 1 步：環境檢查

```bash
python --version          # 需要 3.10+
pip install -r requirements.txt
```

Python 沒裝或版本太舊 → 引導使用者到 python.org 安裝（Windows 記得勾選「Add to PATH」）。

## 第 2 步：訪談（八題，一次一題）

完整訪談腳本在 [`docs/初始設定任務書.md`](docs/初始設定任務書.md)（英文版 [`docs/SETUP_AGENT.md`](docs/SETUP_AGENT.md)）——**如果你讀得到檔案，去讀它**，那份比較完整。讀不到就照下面這份摘要走。

1. **市場** — 台股 `tw` / 美股 `us` / 兩個都要 `both`
2. **要不要「AI 市場重點」段** — 需要使用者電腦上有會網搜的 AI CLI 並已登入。
   選要 → 確認 CLI 跑得動（`claude --version`），把指令或完整路徑寫進 `ai.cli`；沒登入要提醒登入一次（例如 `claude login`）。選不要 → 跳過第 3 題
3. **新聞來源** — ⚠️ **一定要主動把預設清單列出來給使用者看，再問要不要增補**。
   不要只問「你要哪些來源」，使用者面對空白通常答不出來，看到清單才有感覺。
   預設清單見 `config.example.yaml` 的 `ai.sources`。要順便解釋**為什麼要限制**：
   不限制的話 AI 會搜到個人部落格、內容農場、聚合站，品質參差會影響判讀。
   使用者說「都可以」→ 設成 `sources: []`，但提醒他來源品質會參差
4. **自選股** — 代號或名稱皆可（台股自動補 `.TW`）；名稱不確定時查好代號複述確認
5. **技術指標** — `[kline, macd]`（預設）/ `[kline, macd, ma]` / `[kline]`
6. **推播時間** — 建議 08:07 這種非整點（整點是所有人排程的尖峰）。
   有啟用 AI＋查核的話整份流程約 3~8 分鐘，排程時間要算進去
7. **儲存位置** — `local`（預設）/ `none` / `gdrive`（進階，要裝 gws CLI）
8. **Telegram** — 帶使用者用 @BotFather 建 bot（`/newbot`）→ 拿 token → 複製
   `.env.example` 為 `.env` 填入 → 請使用者對 bot 傳一句話 → 用 `getUpdates` 取得 chat_id 填入。
   ⚠️ token 是機密：不要寫進任何會被 commit 或分享的地方，確認 `.env` 已被 gitignore

## 第 3 步：產生設定並實測

1. 依訪談結果寫 `config.yaml`（欄位參考 `config.example.yaml`）
2. `python notify.py --text "設定完成測試 ✅"` → **使用者實際收到才算過**
3. `python brief.py --no-push` → 確認 `archive/` 產出圖、健檢表與簡報。
   有啟用 AI 的話，打開簡報確認「市場重點」段真的有內容（空的多半是 CLI 沒登入）
4. `python brief.py` → 完整跑一次，確認 Telegram 收到文字＋圖片

## 第 4 步：建立每日排程

排程只要叫 `brief.py` 一支，它會自己依序跑完畫圖、AI、查核、推播。

- **Windows**：
  ```powershell
  powershell -ExecutionPolicy Bypass -File install_schedule.ps1
  ```
  會讀 config 的 `notify_time` 自動建立工作排程器任務，用 `pythonw.exe` 執行（完全不跳視窗）
- **macOS / Linux**：crontab
  ```
  7 8 * * * cd /path/to/stock-morning-brief && /usr/bin/python3 brief.py >> cron.log 2>&1
  ```

⚠️ **不要**把整份流程設成「AI 對話式排程」（AI 工具內建的排程任務）：那會每天開一個新對話把使用者的對話列表灌爆，遇到未授權指令還會跳權限詢問等人按允許，沒人按就整份卡死。讓系統排程器跑 `brief.py`，AI 只在需要判斷力的那一段被呼叫。

## 常見狀況處理

| 症狀 | 原因與處理 |
|---|---|
| 市場重點整段變成「蒐集失敗」 | AI CLI 沒登入或路徑錯。檢查 `ai.cli`，請使用者重新登入 |
| `X 找不到 config.yaml` | 還沒做第 3 步，或檔案放錯目錄（要在專案根目錄） |
| 圖片推播卡很久 | Telegram 上行速度問題，`notify.py` 會自動重試並優先走 IPv6；已送出的圖重跑會自動跳過 |
| 健檢表整個空的 | Yahoo Finance 限流（短時間連續呼叫會發生）。`brief.py` 會自動退回最近 7 天內有資料的健檢；等幾分鐘再跑就好 |
| 說「已有另一份晨報在執行中」 | lock 檔還在。確定沒有其他行程在跑就加 `--force` |
